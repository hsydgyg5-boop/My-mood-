إصلاح توافق تشغيل مزاجي على Railway

تم تعديل ما يلي دون حذف قاعدة البيانات أو مجلد USERS:
1) عند فتح موقع ثابت، تكون الصفحة الرئيسية index.html / index.htm / home.html؛ ولا يُستخدم main.py أو app.py كصفحة رئيسية بسبب startup_file قديم.
2) يمنع رابط الموقع الثابت من نشر ملفات Python وسجلات وإعدادات التشغيل كنص عام.
3) تحسين كشف نوع المشروع: ملفات JavaScript الخاصة بواجهة HTML لا تجعل الموقع Node.js تلقائياً، بينما تستمر مشاريع Node التي لها اعتماديات/خادم فعلي في التعرف عليها.
4) تصحيح ملف بدء التشغيل حسب نوع المشروع، دون تغيير أنواع الخوادم الحالية الصحيحة عند إقلاع لوحة الإدارة.
5) إزالة فرض نوع Node.js لمجرد رفع ملف JavaScript منفرد؛ يعاد تحديد النوع من مجموعة ملفات المشروع بعد الرفع.

تشغيل لوحة مزاجي على Railway:
- Procfile و railway.toml يحددان الأمر: gunicorn app:app --bind 0.0.0.0:$PORT --workers 1 --threads 4 --timeout 120
- يتم تثبيت المكتبات من requirements.txt.
- لدوام بيانات المستخدمين، أبقِ Railway Volume على /data ولا تستخدم Wipe Volume.

الاختبارات المنفذة محلياً: فحص صياغة Python، واختبارات كشف أنواع المشاريع (Static / Python / Node.js)، واختبار مسار الصفحة الرئيسية بحيث يعرض HTML ولا يعرض مصدر .py، وفحص سلامة ZIP.
لم يتم إجراء نشر على حساب Railway الحقيقي من هذه البيئة.
