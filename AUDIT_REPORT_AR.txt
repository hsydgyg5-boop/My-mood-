تقرير تدقيق محلي — مشروع مزاجي
التاريخ: 2026-10-20

أهم الإصلاحات:
1. إصلاح استيراد pathlib.Path الذي كان يوقف تجهيز مكتبات Python وقت التنفيذ.
2. التحقق من dependencies في كل تجهيز، وإعادة المحاولة عند فشل تثبيت Python packages، ثم تشغيل pip check وكتابة التشخيص إلى سجل الخادم.
3. الحد الافتراضي لملفات المستخدم 10، مع تعديل الحد من لوحة الإدارة حتى 1,000,000، وتوحيد عدّ الملفات عبر واجهة المستخدم والإدارة.
4. منع الكتابة أو التعديل على أسماء ملفات السجلات الداخلية، وحماية فك ضغط ZIP من المسارات الخارجة والروابط الرمزية والمسارات المكررة.
5. تقوية حفظ قاعدة البيانات والملفات باستخدام كتابة ذرية وملفات مؤقتة فريدة، والتحقق من مدخلات إدارة المستخدم.
6. محرر الملفات يتضمن «فتح الملف» و«حفظ» و«رجوع» وتحذيرًا عن التعديلات غير المحفوظة، ويمنع فتح الملفات الثنائية أو الملفات النصية الأكبر من 5 MiB في المحرر.
7. اختيار اسم السيرفر قبل الرفع، وإدارة الإدارة لسيرفرات وملفات المستخدمين، مع فتح/تحميل والتحكم بالتشغيل عند توفر الإمكانية.
8. لا يظهر تنبيه Railway Volume في الواجهة؛ تبقى حالة التخزين في السجل وواجهة API. يجب ربط Volume فعليًا إلى /data في Railway.

الاختبارات التي نجحت محليًا:
- py_compile لملفات Python الرئيسية.
- node --check للـ JavaScript المضمّن في index.html وadmin_panel.html وlogin.html.
- اختبارات محلية لوظائف الحسابات والملفات والحفظ وعزل ملكية الملفات وإنشاء السيرفر باسم مخصص.
- اختبارات حدود الملفات ورفض ZIP traversal والروابط الرمزية والأسماء المكررة وأسماء سجلات النظام.
- اختبار إنشاء بيئة Python حقيقية وتشغيل مشروع تجريبي، ثم إعادة فحص requirements.txt وتشغيل pip check.
- فحص JSON وقائمة ملفات المشروع وسلامة أرشيف ZIP وعدم العثور على نمط Telegram bot token واضح في نصوص المشروع.

حدود الفحص:
بيئة الفحص لم يكن فيها Flask الحقيقي ولم تتمكن من تنزيل الحزم بسبب عدم توفر اتصال مستودع الحزم. اختبارات مسارات الخادم استخدمت Flask stub لاختبار وظائف المشروع، لذلك لم يُجرَ اختبار HTTP كامل بخادم Flask الحقيقي. لم يتم النشر إلى Railway الحقيقي. لا يمكن ضمان 100% دون نشر تجريبي واختبار بيئة الاستضافة الفعلية.
