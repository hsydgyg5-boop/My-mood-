# مزاجي 2026 — خادم Python مع أنواع Python وPHP وHTML ثابت

## ما الذي تدعمه هذه النسخة؟
- خادم Python: ينشئ بيئة افتراضية `.venv`، يستنتج المكتبات تلقائياً، يكمل المكتبات الناقصة من `requirements.txt`، ويشغّل تطبيقات Flask/FastAPI المعتادة حتى إذا لم يكتب المولّد استدعاء `app.run()` / `uvicorn.run()`.
- خادم PHP: يستخدم `php -S` مع جذر المشروع.
- زر ثالث مستقل لإنشاء موقع HTML/CSS/JS ثابت من دون Python أو Node.js.
- مشاريع Python: يثبّت الاعتماديات الناقصة ويحاول تشغيل تطبيقات Flask/FastAPI الشائعة حتى لو لم يتضمن الكود أمر تشغيل واضحاً.
- موقع HTML/CSS/JS ثابت: يقدّم `index.html` والملفات الملحقة عبر `/site/<folder>/`، ولا يحاول تشغيل HTML كملف Python. إذا كان الأرشيف فيه مجلد مشروع واحد، يُرفع محتواه إلى جذر موقعك.
- كشف نوع ZIP، واختيار ملف تشغيل صحيح، وفحص مسارات ZIP لمنع الكتابة خارج مجلد المشروع.
- API حالة التخزين `/api/persistence/status` (للأدمن فقط) وصفحة صحة `/healthz`.

## قاعدة البيانات المرفقة والحفاظ على المستخدمين
تحتوي `portable_data/db.json` على قاعدة تهيئة الأصلية للمشروع. تُنسخ إلى مسار البيانات فقط إذا لم تكن هناك قاعدة بيانات موجودة؛ لا تُستبدل بها قاعدة موجودة داخل Volume. قاعدة Railway الحالية وملفات المشاريع يجب أن تبقى على Volume الدائم.

## تخزين دائم على Railway
Railway يعيد إنشاء نظام ملفات الحاوية مع النشرات؛ ربط GitHub لا يجعل ملفات التشغيل المرفوعة دائمة. يجب أن يكون Railway Volume مربوطاً بالخدمة على المسار `/data`. عند ربط Volume، يوفّر Railway المتغير `RAILWAY_VOLUME_MOUNT_PATH` تلقائياً، ويستخدمه هذا التطبيق لحفظ: 
- قاعدة البيانات: `db.json` داخل مسار التخزين الدائم.
- ملفات المستخدمين والمشاريع: `USERS/<user>/SERVERS/`.
- ملفات PHP ونسخ قاعدة البيانات الاحتياطية.

**تنبيه صريح:** ملف الكود لا يستطيع إنشاء/ربط Volume تلقائياً بحساب Railway الخاص بك دون صلاحية حساب أو token. بعد التحديث، تأكد مرة واحدة من وجود Volume في Service → Volumes وأن Mount Path هو `/data`. لا تستخدم خيار Wipe Volume. إذا لم يكتشف التطبيق Volume، تظهر رسالة تحذير للأدمن داخل لوحة الاستضافة.

## تشغيل Railway
أمر التشغيل المضبوط: `gunicorn app:app --bind 0.0.0.0:$PORT --workers 1 --threads 4 --timeout 120`
Health check: `/healthz`

للموقع الثابت، ارفع ملف `index.html` إلى جذر المشروع. إذا لم يوجد، يختار الخادم أول ملف HTML صالح تلقائياً.

## إعدادات حساسة
أبقِ `BOT_TOKEN` وأي أسرار في Railway Variables فقط، ولا تضعها في GitHub أو ملفات ZIP عامة.

## رمز Telegram

أزلت رمز البوت المكشوف من القيمة الافتراضية داخل `telegram_bot.py`. أنشئ رمزاً جديداً عبر BotFather، ثم خزّنه كمتغير `BOT_TOKEN` في Railway Variables. لا تحفظ أي رمز داخل ZIP أو مستودع GitHub.
